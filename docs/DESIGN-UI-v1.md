## 0. 结论先说（TL;DR）

1. **界面不是"不好看"，是"信息没有归位"。** 同一条运行信息被摆在 5 个地方（消息流里的 `💭` 气泡、输入框上的 `#workStatus`、底栏 `#statusBar`、顶栏 `#costBadge`、完成后才说一次的 `#hint`），每个地方各显示一部分、各自更新频率不同（1s / 2s / 15s / 只在 done）；用户必须"拼图"才知道这一轮跑到哪、花了多少。依据：`src/web/app.js:447-464`、`569-587`、`748-778`、`490`。
2. **三个长得一模一样、位置也挨着的下拉，生命周期却是三种。** `#modelSel` 写全局配置（`app.js:1302`），`#presetSel` 只随下一条消息生效（`app.js:393-394`），`#permSel` 既写全局又随消息（`app.js:401-402`、`1303`）；"谁说了算"由服务端 `resolveTurnPermission` 决定（`src/web/server.js:120-135`），但界面上只在一条会被刷走的 banner 里说一次（`server.js:825-838`）。这是"我选了自动却按只读跑"这类投诉的**界面侧根因**。
3. **权限确认仍是全屏遮罩。** 代码自己写着"遮罩挡住了输入区的停止按钮"（`app.js:306-308`），补偿办法是在弹窗里再放一个停止按钮（`app.js:296`）——这是绕道，不是修复；遮罩 `position:fixed; inset:0`（`index.html:207`）在结构上永远会挡住 footer。
4. **错误信息"有内容、没排版"。** 上游原文与处置建议在 `src/agent.js:282-324` 被组装成 `⚠ 上游错误：<原文>\n   💡 <建议>`，经 `banner` 到前端后由 `renderBanner` 用 `textContent` 塞进 `.banner`（`app.js:284`、`index.html:193-194`），而 `.banner` **没有** `white-space:pre-line`——换行被折叠，400 字原文和处置建议糊成一段。
5. **没有一个地方告诉新用户"下一步做什么"。** 空对话就是 `<main><div id="chat"></div></main>`（`index.html:321`），唯一引导是缺 Key 时的一条 banner（`app.js:847-850`），且文案说"右上角 ⚙"而 ⚙ 实际是顶栏左起第 3 个元素（`index.html:273`）。
6. **视觉一致性已经漂了**：15 种字号、8 种圆角、108 处行内 `style=`；`#composer` 定义两次（`index.html:166`、`197`），`#workStatus .ws-busy` 两次（`70`、`90`），`var(--cyan)` 根本没定义（`503`）。所以本次**不新造设计语言**，只做"收口 + 归位 + 折叠"。

## 1. 现状诊断（全部带行号）

### 1.1 现有骨架（一句话版）

顶栏 52px（`index.html:52`）里塞了 11 个可交互目标；左侧一个 42px 竖排图标轨（`74-79`）；3 个右侧固定面板 + 1 个左侧面板（子代理 320px `80`、任务 280px `66`、省钱仪表盘 400px `238` 在右，轨迹 252px `98` 在左轨右侧）；主区单列对话（`max-width:860px`，`131`）；底部 footer 里并排放着附件、输入框、权限、模型、预设、推理等级、发送 7 个控件（`322-346`）。

### 1.2 痛点 A：控件拥挤与"开始一次对话"的路径

**控件分布（现状）**

**新用户（桌面版首次启动、无 Key）实际要几步才能发出第一句**：

1. 点 ⚙（`index.html:273`）
2. 在设置里找到「模型与 API Key」（默认组就是它，`index.html:360`）
3. 点某个 provider 的「设Key」（`app.js:1150`）
4. 输入 Key → 确定（`app.js:1151`、`83-91`）
5. 关设置：**只有底部「取消/保存」**（`index.html:495`），没有 ×、没有 Esc（Esc 只绑在 `uiPrompt` 的输入框上，`app.js:89`）
6. 回到底部选模型（`index.html:334`）
7. 到顶栏选工作空间（`index.html:274`）；若还没登记，还要「＋ 新建工作空间…」→ 输入名称 → 系统目录框 → 登记（`app.js:906-917`、`982-997`）
8. 选权限（`index.html:329`）
9. 输入 → 发送（`index.html:342`）

**≥ 6 次点击 + 1 次键入；首次建工作空间则是 9–11 次**。而且第 6/7/8 步的控件分处屏幕**底部、顶部、底部**，视线来回跨约 800px。这不是"控件多"的问题，是**同一件事（开一轮对话）被拆到三个区域**。

**补充事实**：顶栏 `header` 是 `flex-wrap:nowrap; white-space:nowrap; overflow-x:auto`（`index.html:52`），窗口一窄就变成横向滚动条；`#modelSel`/`#permSel`/`#sessions` 被压到 96–130px（`59-63`），模型名和权限名都会被 `text-overflow` 吃掉。

### 1.3 痛点 B：信息层级——工具调用在对话流里怎么显示

- 工具卡有两种渲染入口：开始用 `renderToolStartEvent`（`app.js:208-216`），结束时**删掉旧的、在消息末尾重建一张**（`app.js:471`、`217-278`）。所以一张卡在生命周期里会"跳"一次位置。
- 两张卡插入方向相反：开始卡走 `insertBeforeActiveMsg`（插到本轮 AI 消息**之前**，`app.js:213`、`285-286`），完成卡走 `msg.appendChild`（插到消息**末尾**，`app.js:275`）。而注释（`285-286`）声称"结论与交付物永远位于消息最底部"——实际 `.content`（`app.js:202`）先创建，工具卡永远排在正文**之后**：用户先读到结论，再看到产生结论的证据，顺序与叙事相反。
- **长输出会不会淹没正文**：部分类型已用 `expandableBody` 折叠（bash 输出 >1800 字、`ls` >3 行、通用输出 >400 字，`app.js:244-268`、`util.js:148-169`），但：①卡片**头部不带折叠开关**，收起只能靠"展开全文"按钮；②一次 `read` 30 行、一次 `grep` 命中 8 条，就会连续堆 6–10 张卡；③失败的工具卡不带红色左边框，只在 head 里写 `✖`（`app.js:223`）。
- **耗时/顺序**：只显示 `durationMs`（`app.js:223`），没有相对时间轴、没有"第几步"；并行工具（`src/web/web-io.js` 的 `_activeTools` 配对）在界面上是**串行堆叠**的，看不出并发。
- **轨迹面板是另一套 UI**：`#trajPanel`（`index.html:98-111`、`app.js:609-647`）重复展示同样的工具步骤，字段更全（参数/结果全文），但需要点一下才出现，且与对话流里的卡片**不共享状态**。同一份事实，两套呈现。

### 1.5 痛点 D：错误与权限确认

**权限确认（历史 bug 的结构性残留）**

- `askModal` 创建 `.modal-mask`（`app.js:294`），CSS 是 `position:fixed; inset:0; z-index:50`（`index.html:207`）——**全屏遮罩**，footer 在它下面，输入框和「■ 停止」都点不到。
- 代码的补丁是在弹窗里加一个「■ 停止本轮」（`app.js:296`、`308`），并让 `stopTurnFromButton` 先 `dismissAskModals()`（`app.js:546`）。**结论：遮罩仍挡着界面，只是多了一个逃生按钮。**
- 多个确认会叠加（`pendingAskModals`，`app.js:290`、`310`），只有停止或超时才批量收（`313-317`、`480`）。
- 超时是 120s 且按"拒绝"处理（`server.js:866-871`），但用户看不到倒计时。
- 弹窗标题用 `.modal h3` 的警告黄（`index.html:221`），"会话管理""选择目录"也跟着变黄——颜色语义被稀释。

**错误呈现**

- `.errline`（`index.html:195`）一种样式承担 6 种语义：请求失败（`app.js:443`）、权限应答失败（`439`）、工具未授权（`472`）、上游 error（`481`）、stalled（`496`，用行内 style 改成 warn 色）、done.note（`497`，同样行内改色）。语义靠 `d.style.color` 现场打补丁。
- **上游原文 + 处置建议**：`describeUpstreamError` 返回 `{message, hint}`（`src/agent.js:282-324`），由 `io.print`（`agent.js:1472`）→ `banner` 事件 → `renderBanner`（`app.js:284`）→ `.banner`（`index.html:193`）。`.banner` 没有 `white-space:pre-line`，`\n` 被折叠；长原文不折叠、建议不单独成行、没有"复制原文 / 重试 / 去改配置"入口。
- 错误卡没有"这一条是上游的还是内核的"标签，也没有 request id / 可复制诊断信息——而 `done` 时其实打了 `status` 日志（`app.js:487-488`），只是没上界面。

### 1.6 痛点 E：设置面板

- 结构：8 个左侧分组（`index.html:360-368`：模型与密钥 / 云同步 / 通用与权限 / 调度队列 / 工作空间 / 长期记忆 / MCP / 技能库），弹层 `min(880px,94vw)`（`210`）。
- 体量：**31 个 `<input>` + 4 个 `<select>` + 2 个 `<textarea>` + 25 个 `<button>`**，全部平铺在 8 个 panel 里（实测统计自 `index.html:355-497`）。
- 没有搜索（唯一搜索框是技能库自己的 `#skillSearch`，`index.html:490`），没有"默认值 / 当前值 / 影响"三列，没有"改动作用域"提示。
- 危险操作只有删除类用了 `uiConfirm`（`app.js:974`、`1153`、`1171`、`1327`）；**改 API 地址**（会把已存 Key 发往新地址）只是要求重输 Key（`app.js:1184-1196`），没有"这是凭证级操作"的视觉层级。
- 所有输入框的行内样式几乎逐字重复（`index.html:377-386`、`397-403`、`443-456`…），改一处配色要改几十处。

### 1.7 痛点 F：快捷键与命令

- 全仓前端只有 **2 处** `keydown`：`uiPrompt` 输入框的 Enter/Esc（`app.js:89`）和输入框的 Enter 发送（`app.js:1313`）。
- **没有** `Esc` 停止、**没有** `Cmd/Ctrl+K`、**没有** `Cmd+/`、**没有** `Cmd+Enter`；`Shift+Enter` 靠 textarea 默认行为。
- 生成中按 Enter 不会排队，而是插入一条 `.msg-sys` 提示"上一个任务仍在执行"（`app.js:364-371`）。
- Electron 菜单（`desktop/main.js:131-175`）只有 退出/撤销/复制/缩放/全屏/帮助，**没有**"新对话 / 搜索 / 停止本轮"的加速键；`autoHideMenuBar:false`（`desktop/main.js:225`）意味着 Win/Linux 上还要多一条菜单栏占位。
- 没有命令面板，所以"切模型/切预设/切权限/切会话/打开设置某项"这五类高频动作全部要**用鼠标找到对应控件**。

### 1.8 痛点 G：空态与引导

- 空对话 = 空 `<div>`（`index.html:321`），没有标题、没有示例任务、没有"三步开始"。
- 唯一引导：`keyReady === false` 时 `renderBanner`（`app.js:847-850`），文案是"点击右上角 ⚙ 设置"，但 ⚙ 在顶栏左起第 3 个（`index.html:273`），"右上角"与位置不符。
- 工作空间为空时 `#wsSel` 只有一个"工作空间"占位项（`app.js:893-895`），不提示"你需要先登记一个目录"。
- 模型加载失败时下拉里只有"加载失败，刷新重试"（`app.js:852`），没有重试按钮。

### 1.9 痛点 H：响应式与窗口

- Electron 窗口 `minWidth: 900` / `minHeight: 600`（`desktop/main.js:223-224`），而 WebUI 最窄的业务断点是 `@media (max-width:860px)`（`index.html:64`）——**桌面壳里这个断点基本永远走不到**；窗口拉到 900px 时 header 已进入横向滚动（`52`），底部 7 个控件被压到 44–96px（`206`）。
- 3 个右侧面板 + 1 个左侧轨迹面板各自固定定位、各自用 `body padding` 推开内容（`index.html:31-34`、`35-51`），没有统一的"右栏"；互斥逻辑散在 5 处（`app.js:586`、`644`、`695`、`766`、`779`），每加一个面板就要再补一遍。
- 推挤用 `transition:padding .16s`（`index.html:28`），但面板宽度用媒体查询硬切（`35-51`），动画会跳。
- 无表格塌陷问题（界面不用 `<table>`），但设置里的长列表（`#wsList`、`#schList`）在 880px 弹层里靠 `overflow-y` 滚动，没有列头，信息只能靠 `·` 分隔。

## 2. 设计原则（5 条，每条一句话 + 为什么对 harness 重要）

1. **"离开 10 分钟回来，3 秒内能接上。"**
   常驻区必须回答三件事：现在在做什么（阶段）、做到哪了（步数/工具）、还要多久/多少钱（TTFT、吞吐、上下文、费用）。harness 的任务是按分钟到小时计的，用户不会一直盯着屏幕，**状态不是装饰，是可恢复性**。

2. **高频动作就地，低频配置入库；同一件事只放一个入口。**
   开一轮对话需要的（模型/预设/权限/工作空间）要在输入区一步可达；改 provider、baseUrl、超时这类低频配置放进设置。三个下拉之所以让人困惑，不是因为多，而是因为**长得一样却各管一段生命周期**——界面必须把"作用域"画出来。

3. **正文优先，证据可折；工具是证据，不是正文。**
   对话流的主线是"用户说了什么 / 助手结论是什么"；工具调用、diff、命令输出是**支撑材料**，默认应收成一行，展开才看细节。否则一次 20 步的任务会把结论推到 3 屏之外。

4. **阻断只留给不可逆，确认不能挡手。**
   只有删除会话/删 Key/改凭证地址这类不可逆操作才用模态；权限确认是**每轮会发生好几次**的日常动作，必须是内联、非阻塞、可键盘完成的卡片，"本次放行 / 拒绝 / 始终允许本会话"三档就够。

5. **一个状态一个出口；复用既有 token，不新造语言。**
   阶段、TTFT、吞吐、上下文、费用各只有**一个**权威显示位置（其余位置要么引用、要么删掉）；颜色/字号/间距/圆角从既有变量与一套收敛后的阶里取，不再新增第 16 种字号。**一致性比新鲜感更能降低认知负担**，也直接降低维护成本（现在改一次配色要动 108 处行内样式）。

### 4.1 对话流：消息分组 + 工具时间线卡片

- **现状**：工具卡一张张堆在消息末尾（`app.js:275`），无折叠头、无序号、无时间轴；开始卡与完成卡插入方向相反（`213` vs `275`）；同一份数据在 `#trajPanel` 里再渲染一遍（`609-647`）。
- **改成**：
  1. 一轮助手回复 = 一个 `.turn` 容器，内部固定顺序：`思考（折叠）→ 工具时间线（折叠）→ 正文 → 交付物`。
  2. 工具时间线是一张卡，头部 `工具时间线 · N 步 · 总耗时`＋折叠箭头；默认只展开**前 3 步 + 失败步**，其余收成"展开其余 K 步"。

  4. 点击一行就地展开输出（复用 `expandableBody`，`util.js:148-169`），不再"删卡重建"。
  5. 并行工具用**同一行内并列 chips**（`bash ×2`），不新增第二套时间轴。
- **为什么**：结论优先、证据可折；一次 20 步任务默认只占约 5 行而不是 5 屏；顺序与"先证据后结论"的阅读习惯一致；顺手消灭两套渲染。
- **验收**：
  - 一个 20 步工具的回合，工具区默认高度 ≤ 屏高 40%，且首屏能看到结论开头；
  - 失败步无需展开即可见（有红边 + `✖` + 原因首行）；

## 8. 不做 / 风险 / 取舍

### 8.1 Electron 打包与安全约束（硬边界）

- **CSP `default-src 'self'`**（`index.html:6`）：禁止外链字体、CDN、Google Fonts、远程图标库。所有图标用**内联 SVG 或 emoji**，字体用系统栈（`-apple-system, "Segoe UI", "PingFang SC", "Microsoft YaHei"`，`index.html:28`）。
- **asar 内资源**：不允许运行时读写 `src/web/` 之外的相对路径；新增资源放进现有静态目录并由 `server.js` 的静态路由服务（参考 `INDEX_HTML` 常量）。
- **preload 只能 `.cjs`**（`desktop/preload.cjs`，smoke 有守卫）：新桌面能力（如原生通知、快捷键）**不能**在 preload 里引 ESM；若需要全局快捷键，应走主进程 `globalShortcut` + IPC，且保持"只暴露最小面"的现有纪律。
- **零依赖**：不引入 Tailwind/React/组件库；设计稿用原生 CSS/JS 就是为了证明"不引依赖也能做"。
- **窗口关闭即隐藏到托盘**（`desktop/main.js:246-252`）：任何"关闭前确认"的设计都要考虑这条，别让用户以为退出失败。

### 8.2 无障碍（必须一起做，不能"以后再说"）

- **焦点**：现在全站没有 `:focus-visible`（0 处），键盘用户看不到自己在哪。P0 加全局焦点环（5.5）。
- **对比度**：`--faint` 在 `--bg3` 上 3.26:1（1.10 表），技能卡/KPI/子代理卡都在这个组合上；P2 统一改成 `--dim`。
- **语义**：状态条 `role="status" aria-live="polite"`；命令面板 `role="dialog" aria-modal="true"` + 列表 `role="listbox"` + `aria-activedescendant`；工具卡折叠按钮 `aria-expanded`；emoji 按钮补 `aria-label`。
- **动效**：补 `prefers-reduced-motion`（5.6），`blink` 对前庭敏感用户不友好。
- **键盘可达**：子代理卡/轨迹项的展开目前只能点击（`app.js:639`、`685`），需改成 `button` 或加 `tabindex=0` + Enter/Space。
- **取舍**：无障碍改造会让部分"hover 才显示"的紧凑设计变松，接受——键盘用户占比在桌面端不低。

### 8.3 i18n（中文硬编码的现实成本）

- 现状：`<html lang="zh-CN">`（`index.html:2`），所有文案内联在 HTML 属性与 JS 模板字符串里（如 `index.html:329` 的 200 字 title、`app.js:369` 的拼接提示、`app.js:508` 的错误文案）。
- **不做**完整 i18n 框架（成本高、收益在当前阶段低）。**做**两件小事：① 新增 UI 文案集中到一个 `strings` 对象（只覆盖新组件：状态条、确认卡、错误卡、空态、命令面板，约 40 条）；② 时间/数字格式统一走 `Intl`，不要手拼"分/秒"（现在 `app.js:369`、`576` 各拼一套）。
- **风险**：模板字符串里拼变量（`app.js:369`、`508`、`819`）抽 i18n 时容易丢占位符；不做则未来英文界面要重写这些行。**结论：先集中、不翻译**。

### 8.4 "大改 UI 会打断现有用户习惯"的取舍

- **会打断的**：三件套从输入区/顶栏移入「会话设置」弹层；`#sessions` 下拉变成左栏列表；费用徽标进右栏/设置。
- **缓解**：
  1. P0 不动位置，只加（状态条、错误卡、空态、快捷键）——**纯增量，零迁移**；
  2. P1 迁移三件套时，输入区保留一个 `⚙ 会话设置`，并把**当前模型名**直接印在按钮上（`deepseek-v4-flash · 询问`），用户一眼知道"东西没丢"；
  3. 提供一次性 spotlight（首次进入新版时高亮 3 个变化点，可关闭）；
  4. 一个版本内保留"经典布局"开关（`localStorage` 布尔，只切 CSS 位置，不维护两套逻辑）；下一个 minor 移除。
- **不做什么**：不做可拖拽自由布局、不做主题市场、不做多窗口、不做移动端（`minWidth:900` 前提下没有意义）、不改内核事件名/字段（`progress`/`usage`/`done` 全部按现状消费）。
- **性能风险**：不要为状态条新增轮询。现有 1s（`app.js:421`）、2s（`746`）、15s（`765`、`778`）三个定时器已经够多；状态条只消费 `progress` 事件 + 单个 `requestAnimationFrame` 合帧（现有 `update()` 已是这个模式，`app.js:427`）。
- **数据诚实风险**：上下文占用在生成中**没有**实时 token 数（`budget` 只在 done 计算，`server.js:1093-1101`）。设计稿里写"62%（79K/128K）"必须标 **≈**，实现时用"上一轮 used + 本轮字符估算"并明确 tooltip"估算值"；不要为了好看造一个假精确的百分比。
- **设计稿边界**：`docs/design/ui-preview.html` 是**静态假数据**，双击 `file://` 打开，不请求 `/api/*`、不读 token、不写 localStorage（除主题偏好）。它**不共享**产品 CSS，避免有人误以为样式已经落地。
