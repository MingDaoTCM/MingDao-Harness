# 省钱基准（SAVINGS-BENCHMARK）

> 对应规划：`docs/PLAN-v0.3.0.md` P0-1
> 运行：`node test/bench/bench-savings.mjs`（已并入 `npm run bench`）
> 首期基线：v0.2.8 代码，2026-09-03 记录
> 一句话承诺：**「同一件事，MingDao 比裸调 DeepSeek API 省 X%，且任务做得到底」——本文件就是把 X 变成可复现、可回归的数字。**

## 一、口径（怎么测、凭什么可信）

- **离线零 API 成本**：全部用项目内置的计价函数（`pricing.js`）、精确词表（`tokenizer.js`）、工具 Schema 生成器（`tools/index.js`）、结果截断（`context.js clampText`）做「朴素基线 vs MingDao 优化」对照，不调用任何真实模型端点。
- **确定性**：计价时点固定为**闲时**（`2026-08-15T04:00:00Z`，周六 12:00 北京时间）与**高峰**（`2026-09-02T02:00:00Z`，周三 10:00 北京时间），避免真实时钟跨峰谷导致断言漂移。
- **回归门禁**：每个省钱杠杆都有阈值断言（省 X% 只降不升）；未来任何改动若让省钱幅度跌破阈值，`npm run bench` 直接红灯。
- **诚实边界**：各杠杆是**正交可叠加**的，但不会全部同时生效；「综合 63%」是简单平均（衡量各杠杆各自的省钱幅度），不是"总费用打 6 折"的承诺。实际一次请求同时命中几个杠杆，省多少，取决于任务形态。

## 二、任务集（8 项，随版本复测）

| # | 任务（省钱杠杆） | 口径 | 首期基线 |
|---|---|---|---|
| ① | 缓存命中计价 | 90% 命中 vs 全未命中（命中价 1/30） | **省 84.5%**（¥0.15450 → ¥0.02400） |
| ② | 峰谷避峰 | 闲时 vs 高峰（闲时半价） | **省 50.0%**（¥0.11700 → ¥0.05850） |
| ③ | Batch 半价 | 批量通道 vs 标准（半价） | **省 50.0%** |
| ④ | 工具 Schema 瘦身 | 已用工具剥描述 vs 全量 | **省 52.1%**（1145 → 549 tokens，每轮 ≈¥0.00089） |
| ⑤ | 只读阶段收缩 | 只读子集 vs 全量工具 | **省 52.0%**（1145 → 550 tokens） |
| ⑥ | 工具结果截断 | clampText 上限 vs 原文 | **省 91.7%**（186150 → 15488 tokens） |
| ⑦ | 精确 tokenizer 不虚高 | 精确 BPE ≤ 启发式上界 | exact 740 ≤ heuristic 795（不漏计、不虚高） |
| ⑧ | 推理分级契约 | pro 支持 low/high/max（off 可关）、flash 不发 | 契约通过 |

**综合（简单平均）**：省 **63%**（各杠杆独立口径，非叠加承诺）。

## 三、与其它 bench 的分工

- `bench-cost.mjs`：工具 Schema 瘦身的 **token 数**、A1 两态冻结、护栏前置拦截、Batch 半价的断言。
- `bench-tokenizer.mjs`：官方词表黄金值（12 组 + 长文本精确断言）。
- `bench-routing.mjs`：路由标注集（118 条）。
- `bench-compaction.mjs`：滞回压缩质量集（46 条）。
- **`bench-savings.mjs`（本文件）**：把以上散点的省钱幅度，收敛成一张"¥ 口径 + 任务集 + 基线数字"的统一账本。

## 四、未来如何更新基线

1. 每个版本发布后，跑一次 `npm run bench`，把本文件「首期基线」列更新为该版本的实测数字，并备注版本号。
2. 新增省钱杠杆（如续跑增量上下文、路由省钱归因）时，在 `bench-savings.mjs` 增任务、在本文件增行，阈值对齐「只降不升」。
3. 对外引用"省 X%"时，一律指向本文件，不写死营销数字。
