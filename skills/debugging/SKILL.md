# 系统化调试

## 流程

1. **复现**：构造最小复现用例；无法稳定复现的问题先收集现场信息。
2. **读错误**：完整阅读堆栈与日志，找**第一现场**（最深的用户代码帧），不要只看最后一行。
3. **二分定位**：用日志/断点/注释逐段缩小范围，把"可能"变成"确定"。
4. **假设-验证**：每条假设都要用命令或工具验证，禁止凭猜测改代码。
5. **修根因**：修复后补回归测试，确认原场景与相邻场景都通过。

## 纪律

- 同一方向最多尝试 3 次，失败就换思路，不要反复撞墙
- 修改前先 `read` 现场代码，改动后用 `edit` 精确修改
- 环境问题（版本/依赖/权限）用 `bash` 验证：`node -v`、`python -c "import x"` 等
- 不要把"删掉重写"当作调试手段
