# 安全重构

## 核心原则

**小步、可回退、每步可验证。** 行为保持不变是硬约束。

## 工作流

1. **建安全网**：先跑一遍现有测试；没有测试就先补一条主路径测试，记录当前行为。
2. **小步 edit**：每次只做一个动作（改名 / 提取函数 / 消除重复），不夹带逻辑修改。
3. **每步验证**：跑测试；失败立即用 `undo` 回退，不要带着红测试继续。
4. **顺序**：先易后难——重命名 → 提取函数 → 调整结构 → 最后才动算法。
5. **收尾**：删除因重构而死的代码，更新注释与文档。

## 红线

- 重构和改功能分两次进行
- 不重构没测试覆盖、也不理解的代码
- 大文件先加测试护栏再动结构
