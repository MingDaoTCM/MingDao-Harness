# 测试编写

## 用例设计（表驱动思维）

每个被测函数至少覆盖四类输入：

| 类别 | 内容 |
| --- | --- |
| 正常 | 典型输入的主路径 |
| 边界 | 空、0、1、最大值、恰好等于阈值 |
| 异常 | 非法输入、错误类型、缺失字段 |
| 组合 | 多参数交互的关键组合 |

## 规范

1. 测试名描述**行为**而非实现（"余额不足时报错" > "test_error2"）。
2. 一条测试只断言一件事；断言用真实期望值，不照抄实现。
3. 少 mock：优先真实对象与临时目录；只 mock 网络/时间/随机源。
4. 不测试第三方库本身，测试你的调用逻辑。

## 落地

- 先确认项目已有框架与运行命令（package.json scripts / pytest / vitest 等），沿用现有约定
- 新补测试先跑失败（红），再让实现通过（绿）
- 交付时报告：加了哪些用例、运行命令、通过结果
