# REST API 设计

## 规则

1. **资源命名**：名词复数、层级清晰：`/users/{id}/orders`；动词交给 HTTP 方法。
2. **查询参数**：过滤 `?status=active`、排序 `?sort=-created_at`、分页 `?page=1&page_size=20`。
3. **状态码语义准确**：
   - 200 成功读取 / 201 创建 / 204 删除
   - 400 参数错误 / 401 未认证 / 403 无权限 / 404 不存在 / 409 冲突 / 422 语义错误 / 500 服务端错误
4. **统一错误体**：`{ "code": "...", "message": "...", "details": [...] }`，所有端点一致。
5. **分页**：返回 `total` 与 `items`；大集合用 cursor。
6. **版本化**：`/v1` 前缀或 header，破坏性变更升版本。

## 交付

给出：资源与端点表（方法 + 路径 + 说明 + 请求/响应示例）、错误码表、鉴权方式；实现后同步更新接口文档。
