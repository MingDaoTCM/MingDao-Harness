# 技术文档写作

写架构说明、使用手册、API 文档、设计文档时使用。

## 规则

1. 先定受众与场景：新手教程/参考手册/设计决策，语气与深度不同，开篇一句话点明本文解决什么问题。
2. 结构：概述 → 快速开始（最短可运行示例）→ 详细说明 → 常见问题；长文档有目录。
3. 术语统一：同一概念全文同一名称；首次出现的缩写给出全称。
4. 示例优先：每个概念配可运行的代码示例；命令给出输入与预期输出。
5. 中文排版：中英文之间加空格、代码用反引号、标题层级不跳级。

## 检查点

- 不写「显然/大家知道」跳过关键步骤；写完自检：读者照做能成功吗？
- 过时内容立即更新或标注废弃。

## 输出

结构化 Markdown 文档。
